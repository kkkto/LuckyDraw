# 🍀 Lucky Draw (럭키 드로우)

> **주행 중 기록한 신호등 주변 정차 정보를 재미있는 운세로 바꾸고, 주차 후 요정 캐릭터와 한국어 음성으로 알려주는 Pleos Connect 기반 Android Automotive 앱입니다.**

Lucky Draw는 차량의 기어(D/P), 브레이크 상태, GPS 위치를 활용해 주행 중 운세용 점수를 기록합니다. 차량이 **D(주행) → P(주차)** 상태로 전환되면 대길·길·소길·흉 중 하나의 운세와 요정의 한마디를 보여 줍니다. 주차 상태에서는 위치 기반 힐링 드라이브 코스도 추천합니다.

> [!IMPORTANT]
> Lucky Draw의 점수는 **오락용 지표**이며 안전운전 수준, 신호 준수 여부를 판정하지 않습니다. 신호등에서 멈추는 행동은 안전과 법규 준수를 위해 필요할 수 있습니다. 실제 도로에서는 언제나 교통 신호와 안전 운전이 최우선입니다.

## 1. 주요 기능

| 기능 | 설명 |
| --- | --- |
| 차량 상태 인식 | Android Car API의 D/P 기어 정보 및 Pleos Vehicle SDK의 브레이크 상태 활용 |
| 위치 기반 감지 | 앱에 포함된 국내 신호등 좌표와 현재 위치를 비교해 근처 신호등 감지 |
| 운세 점수 | 100점에서 시작하여 조건을 충족한 신호등마다 10점 차감(동일 신호등 중복 감점 방지) |
| 주차 후 결과 | D→P 전환 시 등급, 요정 이미지, 운세 문구와 점수 표시 |
| 한국어 음성 | Pleos TTS로 운세 안내, 음소거 및 다시 듣기 지원 |
| 힐링 코스 추천 | 로컬 코스 111개 중 위치 기반 추천 코스 3곳 표시 |
| 에뮬레이터 시연 | D 주행 시작, 5초 정차, P 결과 보기 테스트 컨트롤 제공 |
| 다크 모드 지원 | 다크 모드 전환 시 화면 배경이 어두운 테마로 변경되어 야간 주행 환경에서 눈부심과 시각적 부담을 줄이도록 디자인 |

### 운세 점수 규칙

- **시작 점수:** 100점
- **감점 조건:** 내장 데이터에 등록된 신호등의 **30m 이내**에서 브레이크가 **연속 5초 이상** 감지되면 10점 차감
- **중복 방지:** 같은 주행의 동일 신호등은 한 번만 감점

| 점수 | 운세 등급 |5초 이상 정차 횟수|
| --- | --- | --- |
| 90점 이상 | 대길 (大吉) | 0 ~ 1회 |
| 60~89점 | 길 (吉) | 2 ~ 4회 |
| 40~59점 | 소길 (小吉) | 5 ~ 6회 |
| 30점 이하 | 흉 (凶) | 7회 이상 |

## 3. 실행 방법

### 3-1. APK 다운로드 및 에뮬레잍터 직접 설치

Lucky Draw는 **Android Automotive OS (Pleos Connect)** 환경에 최적화된 앱입니다.  
소스 코드를 빌드할 필요 없이 배포된 APK 파일을 에뮬레이터에 바로 설치할 수 있습니다.

1. **에뮬레이터 실행:**  
   Android Studio의 Device Manager에서 **Pleos Connect 기반 AAOS 에뮬레이터**를 실행합니다.
2. **APK 다운로드:**  
   [LuckyDraw v1.0.1 Releases](https://github.com/kkkto/LuckyDraw/releases/tag/v1.0.1) 페이지에서 `luckyy_LuckyDraw_release.apk`를 다운로드합니다.
3. **설치 (Drag & Drop):**  
   다운로드받은 `.apk` 파일을 마우스로 끌어 실행 중인 **에뮬레이터 화면 위로 드래그 앤 드롭**합니다.
4. **실행:**  
   에뮬레이터 앱 서랍(목록)에서 **Lucky Draw** (네잎클로버 아이콘)를 클릭하여 실행합니다.


### 3-2. 주요 기능 시연 방법

에뮬레이터에서 차량 데이터를 직접 제어하기 어려운 경우 앱에 포함된 시뮬레이션 모드를 활용할 수 있습니다.

1. **D 주행 시작:** 주행 상태를 활성화하고 운세 기록을 시작합니다.
2. **5초 정차:** 시연 버튼 또는 Pleos Virtual Console의 브레이크 입력으로 정차 조건을 재현합니다.
3. **점수 확인:** 시작 점수 100점에서 조건 충족 시 90점으로 변경되는지 확인합니다.
4. **P 결과 보기:** 주차 상태로 전환하여 운세 결과를 표시합니다.
5. **결과 확인:** 요정 캐릭터, 운세 등급 및 메시지를 확인합니다.
6. **힐링 루트:** 주차 상태에서 위치 기반 추천 드라이브 코스를 확인합니다.
7. **다크 모드:** 다크 모드로 변경하여 어두운 배경 테마가 적용되는지 확인합니다.

> **참고:** 실제 GPS 기반 정차 감지는 등록된 국내 신호등 좌표 30m 이내에서 동작합니다. TTS 음성 출력 및 내비게이션 연동 기능은 실행 환경에 따라 추가 설정이나 검증이 필요할 수 있습니다.

## 4. 테스트 환경 및 설정 (중요)

### 4-1. 에뮬레이터 GPS 제한

앱에 내장된 `app/src/main/assets/traffic_lights.json`에는 **국내 신호등 약 20,895개의 좌표**만 저장되어 있습니다. GPS가 등록된 신호등의 **30m 이내**에 들어와야 해당 신호등을 감지할 수 있습니다.

따라서 기본 에뮬레이터 GPS 위치가 국내 신호등 데이터 범위 밖이거나 신호등 좌표에서 30m 이상 떨어져 있으면, **브레이크를 5초 이상 눌러도 감점되지 않습니다.** 이때 앱에는 다음 안내가 표시될 수 있습니다.

> 현재 GPS가 국내 신호등 범위 밖입니다 · 하단 시뮬레이션 버튼 또는 국내 좌표를 사용하세요

이는 일반적인 GPS 테스트 제약이며, 해당 상황에서는 감점이 차단됩니다.

### 4-2. 방법 A — 앱 내 시뮬레이션 모드 (권장)

**국내 신호등 좌표를 직접 지정하지 않아도 실행 흐름을 보여주는 가장 간단한 방법입니다.** 에뮬레이터로 인식된 환경에서는 앱 화면 하단에 시연용 컨트롤이 나타납니다.

1. 앱 화면 하단의 **`D 주행 시작`** 버튼을 누릅니다.
   - 시뮬레이션 모드가 활성화되고 테스트용 가상 신호등 `demoLight`가 자동으로 할당됩니다.
2. **Pleos Virtual Console**에서 브레이크 입력을 **연속 5초 이상** 유지합니다.
   - 앱 하단에 **`5초 정차`** 시연 버튼이 있는 경우 해당 버튼을 이용해 정차 조건을 시연할 수도 있습니다.
3. 점수가 **100점 → 90점**으로 변경되는지 확인합니다.
4. 앱 하단의 **`P 결과 보기`**를 눌러 주차 상태 및 운세 결과를 확인합니다.
5. 운세 등급, 요정 이미지, 안내 문구가 표시되는지 확인합니다. TTS는 실행 환경에서 실제 음성이 출력되는지 별도로 확인합니다.

> [!TIP]
> 감점 테스트 중에는 동일 신호등에서 여러 번 브레이크를 유지해도 **중복 감점되지 않습니다.** 추가 감점을 테스트하려면 새로운 시연 주행/신호등 조건을 마련해야 합니다.

### 4-3. 방법 B — 국내 GPS 좌표 사용

1. 에뮬레이터의 위치 설정에서 **국내 실제 신호등 좌표**를 가상 GPS 위치로 지정합니다.
2. 해당 좌표가 `traffic_lights.json`에 존재하며, 현재 위치가 신호등의 **30m 이내**인지 확인합니다.
3. D 상태에서 Pleos Virtual Console로 브레이크를 **연속 5초 이상** 유지합니다.
4. 감점이 적용되는지 확인한 후 P로 전환하여 운세 결과를 확인합니다.

**주의:** 단순히 GPS를 대한민국의 임의 좌표(예: 서울 중심부)로 설정하는 것만으로는 충분하지 않습니다. **내장 JSON에 포함된 신호등 좌표** 근처여야 합니다. 위치 데이터가 오래되었거나 정확도 조건을 충족하지 못하면 감점이 발생하지 않을 수 있습니다.

## 6. 알려진 한계 및 참고 사항

- **신호등 상태 미수집:** 신호등 좌표와 브레이크 지속 시간을 이용하며 실제 신호 색상, 교통 흐름 또는 합법적인 정차 이유는 판단하지 않습니다.
- **GPS 데이터 범위:** 내장된 국내 신호등 데이터 범위를 벗어나면 감점이 차단됩니다. 좌표의 출처·라이선스·갱신 주기는 별도 확인이 필요합니다.
- **TTS 검증 범위:** Pleos ON_DEVICE TTS 코드가 구현되어 있으나 실제 차량 스피커 출력 및 다른 오디오와의 동작은 추가 검증이 필요합니다.
- **내비게이션 연결:** 힐링 코스 선택 시 외부 앱으로 `geo:` URI를 전달하는 코드가 있으나, 보고서에서 확인한 환경에서는 **실제 내비 경로가 생성되지 않았습니다.**
- **코스 정보:** 추천 코스 거리·소요 시간은 추정치이며 실시간 경로 탐색 결과가 아닙니다. 별점 또한 로컬 JSON에 저장된 값입니다.
- **검증 상태:** 보고서 기준 `:app:assembleDebug` 빌드 성공. 실차 통합 테스트 및 자동화 테스트 완료를 의미하지는 않습니다.
- **추후 추가기능:** 앱 유저 간 드라이브 코스 추천과 리뷰, 댓글을 다는 기능을 추가할 예정입니다.
